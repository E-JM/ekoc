# eko FFI —— 三向需求与选项分析

状态:**分析+裁定档**。随档裁定 F1–F23,O 表 17 项全部已闭或作废;
升级路径见 §8。

范围裁定:

1. **三向完整设计**——内部通道(prelude→OS)、用户向 C FFI(Unsafe
   门控)、嵌入 ABI(host↔eko)一次分析,不做单向前裁;
2. **伞形**——FFI 档是波次伞,机词族、位算、`0x/0b` 字面量、
   `Bytes↔[]U8` 零拷贝、FFI 调试定宽 hex 五项随波预约(02-syntax.md
   §5/§7、08-builtins.md §3.5)一并纳入;
3. **分析先行**——需求清单、选项空间、张力与开放问题;定案文档另起;
4. **设计前提(用户提出,待定案确认)**——编译器可能采 C 后端:
   eko 先编译为 C 源码,再调 C 编译器成机器码。规范层 07 总纲是
   "直编机器码",C 后端是实现策略而非规范承诺;FFI 设计不得与它
   互斥,且可借它落地——影响面见 §3.10。

随档裁定(本轮共同裁定):

- **F1 能力实现采弱读**——能力值的配给代码由编译器生成(CLI 场景),
  操作实现走闭包束;案 A(操作 intrinsic 化)出局,O1 就此收敛于
  B′(§3.12);
- **F2 用户不可自建能力类型**——能力类型集保持 built-in 封闭;
  闭包记录束为用户域惯用法;不可伪造用户令牌(S5)显式拒(§3.12);
- **F3 嵌入应用面 γ′ 先行**——宿主直调 eko 导出入口,应用面作普通
  值;β(宿主注册能力类型)缓议为 O17 备胎(§3.12)。

  授权轴移至链接面(extern 声明静态可见+符号链接即授权);不可恢复
  错误(segfault 级)=abort。回写面:06 §2.1 Unsafe 行删、§2.2"清单
  即全部表面"改写为"OS 面",01 总纲两轨措辞,`--sandbox` 语义=拒
  extern 编译/链接,06 §7 定理改述;O15 作废(§3.13 G1)。

- **F11 整数位算=域词函数族**(第三轮,G2)——`UInt/Int.band/bor/
  bxor/bnot/shl/shr`,无运算符;机词不配位算;移位/截断语义已随 F15 定;

- **F12 首波禁异步回调**(第三轮,G3)——禁=词汇缺席非语义承诺;
  trampoline 与未来句柄同构,不堵未来;线程模型随 O7(§3.13)。
- **F13 包装层索取并真用**(第三轮,G4)——触及 OS 面的包装按语义
  索取自然能力并真用(预检/沙箱/衰减);装饰性能力参数被禁;
  libm 类不索取(§3.13)。
- **F4/F6/F9 转正**(第四轮)——F4 细化:extern 可公开可 `_` 私有,
  包装是推荐惯例非强制;F6 统一 `C.*`(`C.Ptr.Void`/`C.Size`/
  `C.get_errno`),白名单三档;F9 转正(§3.13)。
- **F5 担保词拼写 v3 + F14 库归链接层**(第四轮)——`= extern "sqrt"

  形式永远最短(符号+至多一词)(§3.13)。
- **F7 位算无运算符整条转正**(第四轮)——预约解除;解析域归
  Bytes;0x/0b 依期望型细则入档(§3.13)。
- **F15 O9 四件套**(第四轮)——机词零算术(能持/比/显/渡);域词

  total 舍入、机→域恒全;§3.10 wrap 一票前提(机词参与计算)
  随之落空——wrap 只发生在 C 侧(§3.13/§4.1)。
- **F16 布局记录包**(第四轮,O5)——`ctype` 显式标记(三塌点证);
  字段限机词;按值过界唯一;出参 shim 吸收;完整重声明;无取址
  (§3.14)。
- **F17 `C.In T` 读借用**(第四轮)——copy-in 调用期审计契约;读类
  `&` API 去 shim,写类仍 shim(§3.14)。
- **F18 不透明薄面**(第五轮,O8)——签名入契约,`eko_value` 不透明,
  快路归 D2(§3.15)。
- **F19 持值与线程**(第五轮,O7)——裸 retain/release;任意线程
  三句协议:无全局态/跨界即共享即原子/束线程安全束作者担保(§3.15)。
- **F20 shim 共用解析面 + Conc 调度归束**(第五轮)(§3.15)。
- **F21 wrap/unwrap 双原语 + F22 prelude 零 libc + F23 宿主符号
  保留**(第六轮,O1 尾)——README 开放问题终答:extern 词法统一,
  intrinsics 不增(§3.16)。

三向必须同裁的理由随 §3.1 浮现:内部通道的最硬需求(派生能力表)
会把方向二、三的机制拉进来,单向前裁必然返工。

## 3. 深入分析

### 3.1 内部通道:tee 筛子与三案

**筛子论证。** `Out.tee: (Out, (String) !-> _) -> Out` 要在 prelude 层实现:
拿到真 `Out`,造一个**新的 `Out`**,其每次写入既写底层又报观察者。无论通道
是哪种,tee 都要求"用普通 Eko 组合出一个新能力值"。这一要求筛掉一切
"能力操作是编译器认名"的浅案。

| 案 | 机制 | 过筛方式 | 代价 |
|---|---|---|---|
| A 逐函数 intrinsic | 编译器识别 `Out.println` 等名字,直生成 OS 调用 | tee 需编译器内建"派生能力构造"(每能力一套包装魔法),或 intrinsic 内部经分派表转发——**实现上塌缩为案 C** 还多付每函数名字挂钩 | prelude 逐函数编译器化,D1 承诺逐个漏;R1.3 增量成本最高;能力类型在编译器里获得第二身份 |
| B extern 词法 | prelude 源码声明 `extern`,调宿主导出的 host ABI(如 `eko_fs_open`) | tee 需宿主 ABI 提供"用 eko 闭包包一个新能力"的原语——**方向三的机制被迫前移**;每加一个派生,host ABI 长一行,或宿主提供通用"闭包束构造器"(又回到 C) | host ABI 成为一半规范,与 D2 冲突(→O8);派生面 = 宿主面,违反"no host magic"的字面 |
| C 能力即闭包束 + 微原语 | 宿主交付的能力,内部即"世界触碰闭包的束"(每操作一个 `!->` 闭包);编译器仅为 prelude 开一枚**纯 unwrap**(把能力值还原为束),此后一切——println 到 tee——都是普通 Eko 组合 | tee=普通组合:unwrap、包观察者、重新成束;`Out.null`=哑闭包束;`In.from_lines`=读表闭包;`Clock.frozen`/`Rand.with_seed` 同理 | 束形是宿主↔编译器的内部约定(不入语言规范);性能多一跳间接;**prelude 可能一行 extern 都不需要**——README 的开放问题被改写为"束构造归属",见下 |

案 C 的推论值得单独记:**通道问题可能消解**。prelude 不触 OS——OS 调用
住在宿主构造的闭包里,prelude 只组合;`extern` 词法因此退化为**纯用户向
特性**,prelude 内的"纯 extern 仅 prelude"(A3)条款在案 C 下可能一行
都用不上,或收窄为 unwrap 一枚纯原语的"仅 prelude"。三案对 README 开放
问题("extern 声明 vs 编译器 intrinsics")的回答分别是 B、A、
"都不是——束由宿主构造"。

案 C 同时是方向三的自然桥:宿主构造能力 = 宿主构造闭包束,嵌入 ABI 与
内部通道**共用一个面**(R3.1 与 R1.1 合并),这解释了为什么三向必须同裁。

倾向(不下定案):案 C 承诺面最小、机制唯一性最好;但案 B 对"OS 调用
可读可 grep"更友好(源码里看得见 `eko_fs_open`)。定案时须裁:束形约定
的规范地位(实现域 or 规范级 host ABI)、unwrap 的词法形状与仅-prelude
条款的措辞。C 后端前提下 B/C 汇流为联合案 B′——见 §3.10。

### 3.2 世界可靠性定理的缺口与 Unsafe 附着

06 §7 证明第 1 步:"设位只源于**需要能力值的 builtin 调用**"。规则 7 让
extern 默认置位——extern 不是 builtin,证明缺一前提。两种补法:

- **(i) 权限补**:extern 调用点必须持有 `Unsafe` 能力值。定理陈述
  "涉世 ⟹ 用过能力"原样成立——`Unsafe` 是能力;01 的总纲
  "capabilities gate every contact with the world"保住。
- **(ii) 弱化定理**:允许裸 extern 置位,定理改述为"涉世 ⟹ 用过能力
  **或调过 extern**"。诚实轴(有 `!`)保住,权限轴破——一个 extern
  不经任何授权即可 format 硬盘。

倾向(不下定案):(i)。附着位置再裁一刀:

> **修订注(F10)**:本节倾向 (i) 已被覆——访谈后裁定取消 `Unsafe`,
> 授权轴移至链接面(声明静态可见+符号链接即授权);定理改述与回写
> 面见 §3.13 G1。本节保留作为历史分析。

| 附着 | 形状 | 评 |
|---|---|---|
| 签名参数式 | extern 声明的签名显式含 `Unsafe` 首参(与 `Out`/`Fs` 同款):`sqrt: (u: Unsafe, x: F64) !-> F64 = extern …` | 与能力语法完全同构;UFCS 照常;调用点可见授权;无 ambient |
| 声明级 | "extern 声明所在处即需 Unsafe" | 授权来自**位置**=ambient authority,与 A4 冲突,排除 |
| 模块级 | 特殊 foreign 模块 import 即授权 | 同上,且 import 是名字授权非世界授权,混轴,排除 |

配套:证明补一步("extern 调用要求 `Unsafe`,或位于 prelude 且审计"),
规则 7 措辞从"默认置位"细化为"恒 `!` + `Unsafe` 参数(用户向)/prelude
审计例外"。prelude 自用的 extern(案 B)或 unwrap(案 C)是否吃
`Unsafe`、还是凭"宿主符号即权限"免检——随 O1 案别走,记入 O2。
用户纯 extern 若依 §3.11 开放,"审计例外"的成员资格不再限于
prelude——定理与规则 7 的措辞随之改写,记入 O16。

### 3.3 安全姿态谱系:地板措辞

07 §4.1"内存安全是语言的地板,不是能力"与 C ABI 的 UB 本性正面相撞。
谱系三档:

| 档 | 内容 | 得失 |
|---|---|---|
| (a) 审计式 UB 豁免 | extern 声明是签名契约,错签名/坏库=UB,文档明示"承诺到符号为止" | 零边界成本;地板措辞降级为"地板在边界内侧";conformance 只测声明层 |
| (b) 全 checked 边界 | 一切 extern 经生成的 stub:签名错链接期查、参数域检、abort 捕获映射 | 地板全保;stub 成本、每调用开销;段错误仍无法 stub(子进程隔离另计,过重) |
| (c) 分层 | 白名单类型(标量/机词/Bytes/String)的签名错不可能——marshalling 有界检查;"指针/布局"词汇显式标 UB,仅 `Unsafe` 下可用 | 与白名单(R2.2)天然对齐;UB 面收窄到显式词汇,可枚举可审计 |

倾向(不下定案):(c),配一句定位措辞候选:"跨界后,`Unsafe` 是你签字
的审计"。档位与 O1 案别正交(内部通道无论何案都不涉 UB——宿主符号是
编译器/宿主共同审计面)。

### 3.4 环定理存续(小论证)

堆图的边=堆对象内部槽位的引用(07 §3)。逐条检查 FFI 通道:

- 宿主/foreign 持 eko 值:引用住在宿主侧计数里,**不是堆内边**(06
  §2.4"持值即持引用"的精确含义)——定理边集不变;
- foreign 不能构造 eko 值(只能调用 eko 函数获得值/句柄),不能写字段
  (无词法,C4)——"可变回写"通道原样封死;
- 回调捕获的 eko 闭包:捕获即快照,构造序仍只降不升;
- 唯一破口:若未来开放**布局子语言 + 写回**(foreign 直接读写 eko 对象
  字节),则"可变回写"重开,环定理与 RC 完备性同毁。

结论:marshalling/句柄案下环定理原样成立,零新前提;布局写回案(若
未来开)必须连同内存策略整体重审——这是把 by-value 结构体写回钉死在
本波之外(仅读或仅 marshalling)的独立理由。RC 侧对偶:宿主持值不走
计数协议=悬垂=地板破,故 R3.2 是**地板条款**,不可让渡为优化细节。

### 3.5 失败映射表

| C 侧现象 | eko 词汇 | 依据 |
|---|---|---|
| 返回码/errno/输出参数 | extern 只搬运标量;包装成 `Result` 是**库层手工**(每库错误协议是库域知识,FFI 不自动映射) | C3、R2.4 |
| NULL/哨兵值 | 同上,`Option` 包装在库层 | C3 |
| 段错误/SIGABRT/SIGSEGV | 进程 abort,与 panic 同机制,不可捕 | B7、06 §3.3 |
| longjmp/C++ 异常跨界 | **定义为 abort**(禁止而不可检——链接期查不了;诚实的选择是定义行为) | B7 |
| EINTR | 宿主 ABI 层可内重试(06 §3.2 先例);用户 extern 不承诺重试 | 06 §3.2 |
| 变参函数(printf 式) | 首波禁:签名必须完全,marshalling 需定型 | R2.2 |

### 3.6 回调、重入、生命周期

- **同步回调**(qsort 比较器):编译器生成 trampoline,存活期=调用期;
  foreign 侧只见不透明 fn 指针+context。回调箭头照常标注(`!->`/`->`),
  位住箭头不感染数据(A7)。
- **异步注册回调**(foreign 存下回调以后调):闭包引用的持有期超出调用
  期——首波**禁**,或给显式"回调句柄"+手动释放(代际句柄+`with_*`
  范式,B3)。开 O6。
- **重入**:foreign→eko→foreign 自由,栈照常;自尾递归保证不受跨界影响
  (尾位是调用者侧事实)。
- **回调内 panic**:abort 传播进 foreign——foreign 不 unwind,两档相认
  (07 §3 末条同款)。

### 3.7 并发、取消、线程

- **取消**:取消施于世界调用边界(06 §8)。extern 调用是**不可中断的
  边界**——C 帧不可安全打断;语义即"scope 退出等 world 调用返回",与
  "纯任务不终止则挂起 scope"的既有诚实条款(06 §8)同款记诚,不新开
  词汇。
- **foreign 线程进 eko**:无运行时系统(B8),无全局锁可依;语言无全局
  可变状态,原子计数已在(07 §4.2)。嵌入 ABI 二选一:任意线程可调
  (协议=计数原子+无全局状态,最宽)或仅注册线程(最窄)。Conc 任务
  与 foreign 线程的汇合(谁跑 scope、join 语义跨不跨界)开 O7。
- **数据竞争**:不可变值+原子计数下,foreign 只要不写 eko 值(无写
  词汇)则无竞争;foreign 自身数据是其自己的事。

### 3.8 单态化与泛型禁令

extern 签名含类型变量 ⟹ ABI 无法定型(C 符号无模板语义)。裁定面只有
一档:**禁**——声明处编译错误;泛型包装属 prelude/库层(对 extern 基
函数做 `List.map` 是普通 Eko 泛型,不受限)。机词转换族(C1)使
marshalling 词法完备,是禁令的对价。

### 3.9 链接与平台

- extern 声明入模块接口(D3);符号解析在链接期,模块 DAG 不动;
- 库名/符号名是声明的一部分;平台差(符号修饰/库名)归宿主与库层多模块
  (C5),不开条件编译后门;
- host ABI(案 B)或束形约定(案 C)的**规范地位**是 O8:维持"编译器
  细节,不入契约"(宿主自便,测试靠派生能力)或升格规范面(一致性
  测试可测宿主);
- 静态/动态链接首波不约,实现域。

### 3.10 C 后端前提的影响

前提地位先行:规范不强制后端(07 总纲"直编机器码"),FFI 的规范面
不得依赖"C 是唯一后端";但三件事成立——(a) 设计不得与 C 后端互斥;
(b) 实现指导可按 C 后端给(首波最可能形态);(c) 首波目标 ABI 本就是
C ABI(O14),C 后端下它是零转译层。

**通道:B/C 汇流。** C 后端下案 B 无 bespoke host ABI 可言——prelude
直接 extern libc/OS 符号(`open`/`read`/`clock_gettime`/…),"宿主"
即生成的 C 入口;案 C 的束=C 函数指针结构体,与 C 后端天然同构。两案
汇流为联合案 **B′**:词法面=extern(案 B),运行面=能力即闭包束
(案 C)——宿主(生成的 C)构造真束直指 libc,prelude 组合派生束,
tee 筛子在 B′ 下自然过筛。B′ 对 README 问题的回答:"extern 词法,
但 OS 面的 extern 住在宿主/prelude,束是桥"。O1 的三案谱系因此
收拢为 B′ 对 A 的选择。

**布局(T1 再评估)。** 诱惑:C 后端下"生成的 C 结构体"看似可以直接
跨给用户 extern。陷阱:承诺布局=冻结代码生成——拆箱/栈配/计数消减
(07 §5)与 B5 直接触碰。白名单 marshalling 在 C 后端下标量/Bytes
近零成本(同构直传,不可变值语义等价);成本表如实记"规范承诺值
跨界,实现可零拷贝"。O5(布局子语言)在 C 后端下更诱人而代价不变
——钉死理由见 §3.4,不随后端松动。

**机词与 ABI。** `I8..F64/U8..U64`↔C 类型直映,定宽即 C 定宽;
位算直映 C 运算符——C 的无符号回绕与机词 wrap 同构,这是 O9 的
一票(机词 wrap,与 C 对眼)。

**嵌入。** 产物=对象文件/静态库;符号面可枚举=用户 extern 符号+
运行符号(alloc/retain/release/panic 入口);宿主链接即嵌入,R3.6
直答;host ABI(若 B′)=libc+束构造器,规范地位随 O8。

**一致性。** cc 依赖进构建矩阵,conformance 须经 cc——平台矩阵成本
如实记;backtrace 格式(README 开放问题第二条)受 C 编译器影响,
措辞需留实现域余地。

### 3.11 用户纯 extern:担保的三种形状

背景:A3 现状=纯 extern 仅 prelude。本轮用户裁定输入:**用户需要在
提供保证之后才能声明纯函数**——即纯例对用户开放,担保显式化(R2.9)。

**诚实税(开放的理由)。** libm 的 `sqrt`、`crc32` 这类真纯函数在
"恒 `!`+`Unsafe`"下被冤枉标注:`!` 是"可能触世"的断言,对可证不触
世的函数是假话。规则 3 的精神是标注必须如实——强制 `!` 把断言写在
可证不触世的函数上,形式合规而语义失实。且税会传染:libm 包装层
全线 `!`+`Unsafe`,位纪律被稀释。用户的输入修复的是诚实轴的另一侧:
现状保住了定理,代价是箭头说谎。

**定理代价(开放的代价)。** 定理从**结构性**保证降为**审计基(TCB)**
保证。prelude 纯 extern 本就是 TCB——只是成员封闭(编译器厂商);
开放=成员扩到模块作者。Rust unsafe 先例:可行,但 06 §7 须改述为
带 TCB 条款的形式。

**担保语义必须是两条**(缺一定理漏一块):

1. **无世界接触**(bit 轴):不调 I/O/信号/时钟/熵。校准:program-
   internal 状态非 world(06 §8 join/cancel 纯的先例)——C 静态状态
   按此定义是 bit-pure;
2. **可重入/线程安全**(Conc 轴):纯 extern 可能被两任务并发调;目标
   若持内部静态状态(strtok 式),并发=C 数据竞争+可观察乱序,06 §8
   "纯任务确定性"论证破。此条**不来自位系统**,来自并发确定性——
   是担保词汇容易被漏写的半边。

**三种形状:**

| 形状 | 机制 | 得失 |
|---|---|---|
| (a) 担保词 | 声明写 `->` + 显式担保词(命名随 O16):`sqrt: (F64) -> F64 = extern … 担保形` | unsafe-block 同构:开户即担责;TCB 全开;接口须披露该模块含审计纯 extern |
| (b) attribute 交叉核验 | 仅当目标符号在可见 C 头文件带 `__attribute__((pure/const))` 方许 `->`;C 后端下编译器读得到(§3.10) | 机器可核,GCC/Clang 既有审计词汇;局限:attribute 语义与两条担保不严格重合(pure 允许读全局内存;const 近条 1 而不含条 2),未注解的真纯 C(自写库)被拒——保真而窄 |
| (c) 登记表 | 编译器随附审计符号白名单 | TCB 收回编译器厂商;用户自绑 C 库进不来——不满足 R2.9,列谱系端点 |

**爆炸半径(任何开放形状都须过):**

- 纯 extern **无能力即可调**:`--sandbox` 与嵌入授权清单看不见它——
  授权清单的盲区从"无"变"审计基";缓解候选:接口披露+宿主/编译器
  拒载开关(O16 细节);
- 测试(09 §6"测试永不触世")与 `Clock.frozen` 式确定性同降为审计基;
- 撒谎的运行期行为=世界接触从纯函数发生——不可 conformance(只有
  声明层可测),如实记。

倾向(不下定案):(a)+(b) 分层——担保词开户,头文件 attribute 可核
则核(核不过报诊断还是放行,随 O16);(c) 不满足需求。担保词与
`Unsafe` 正交:纯 extern 无 `Unsafe` 参(纯函数不需能力),不纯 extern
照 §3.2 吃 `Unsafe`。

### 3.12 能力构造权与"自建能力"(用户裁定输入)

用户前提:"能力的实现在编译器层面;从 `main` 请求时由编译器放入。"
前提有两读,命运不同:

- **弱读(构造权)**——能力**值**的配给代码由编译器生成(CLI 场景);操作
  实现走束(B′)。与既有裁定完全相容:06 §2.1"构造属于宿主与入口点"
  在 CLI 下的宿主=编译器生成的入口(§3.10"宿主=生成的 C");嵌入
  宿主替换之;`Unsafe` 同机(opt-in 由启动旗标/宿主决定,配给同源)。
- **强读(操作权)**——每个能力的**操作**是编译器 intrinsic,即 §3.1
  案 A。tee 筛子判死:R1.2 要求派生表在 prelude 层零宿主魔法,操作
  intrinsic 化后 `Out.tee` 们逐个变编译器魔法,D1 承诺逐分泄漏。

结论:**[已裁 F1]** 前提按弱读采纳——能力值配给编译器生成(CLI),
操作走束;案 A(强读)出局,O1 收敛于 B′。

**定理侧理由(为什么"用户不可自建"是对的)。** 06 §7 证明第 2 步:
"能力不可伪造:仅由 `main` 参数、宿主、纯派生构造"。能力类型集
封闭(built-in)正是这条前提的形状;若用户可声明能力类型,
unforgeable 破(记录可自由构造),前提须重写。封闭集是定理的便宜性。

**[已裁 F2] 用户域的替代惯用法:闭包记录束。** 语料已两次踩到同一惯用法:
05 §12"模块不入值位:要值,用闭包的记录";06 §5.5 `mk_logger`
纯工厂产 `!->` 闭包。`!->` 合法居于记录字段(§5.2 只禁 `?` 居
字段)。于是用户域的"能力"拼写:

```
Db: type = [query: (Sql) !-> Result Rows DbError, exec: (Sql) !-> Result _ DbError]
```

- 权限:持有即授权,与能力同构;伪造假 `Db` 造不出真行为(真行为
  底层要真能力/`Unsafe`);
- 衰减:纯函数构窄记录(`Fs.read_only` 同款,自写);
- mock:记录自由构造——派生面即构造面,测试天然(09 §6 零扩展);
- 位:`!->` 住字段箭头,调用点照常置位;世界接触最终落在闭包体内
  的能力调用/extern——定理不动。

缺一件:**main 清单可见性**。`Db` 的授权在清单上显示为其底层的
`Net`/`Unsafe`,不显示"Db"。这是诚实的:清单审计 OS 面;域面授权
流经值——闭包捕获能力本就是 corpus 世界的常规("copying is
delegation",06 §2),清单是入口审计,不是授权流的全部。

**情景清单(什么情景需要自建?):**

| 情景 | 需要新机制? | 答案 |
|---|---|---|
| S1 库包外部资源(DB/HTTP/GPU) | 否 | 闭包记录束;清单经底层能力显示 |
| S2 域面衰减(只读视图/受限令牌) | 否 | 纯函数构窄记录 |
| S3 嵌入宿主的应用面(editor/engine 的 Buffer/Clipboard) | **是——真缺口** | 两路线,见下 |
| S4 测试缝(DI) | 否 | 记录自由构造即 mock |
| S5 不可伪造令牌(模块间不信任) | 否(且被拒) | 无身份比较(07 §9),可验证的不可伪造 token 无词法基础;语言不设模块间不信任轴 |

**S3 是唯一真缺口**:嵌入宿主的应用面进不了 main 清单(清单只收
built-in 能力类型,06 §2.1)。两条路线:

- **γ′ 直调导出函数**:嵌入宿主不走清单给应用面,而是直接调 eko
  导出的入口(如 `init: (s: EditorServices) !`),应用面=宿主经束
  ABI 构造的普通记录值。零新词法;main 清单保持纯 OS 面;审计面从
  清单移到入口签名(静态可 grep 不丢);位经记录内 `!->` 照常。
- **β 宿主注册能力类型**:嵌入 ABI 允许宿主登记新能力类型进 manifest。
  清单可见性保住;但"built-in types"(06 §2.1)须改写、清单类型
  检查协议扩容、每型的派生面要宿主配合——机制成本实。

**[已裁 F3] γ′ 先行**——零词法、与"授权流经值"的既有世界观
同构;β 缓议为备胎,待嵌入生态实证需要清单级应用面审计再启。
记 O17。

### 3.14 结构体过界:S1–S4 访谈与裁定(第四轮)

用户四答(S1 stat 出参/S2 sockaddr 入参"eko 类型独立,C 结构须重声明"/
S3 如上/S4 div 按值返回,记 `[quot: Int, rem: Int]` 或元组)。三堵墙:

- **墙 1 不可变性**:草图 `stat(b); b.size` 要求 C 写 `b`——字段赋值
  不存在(03 §1),出参在 eko 无诚实词法;
- **墙 2 宽度**:`div_t` 的 `int`=32 位 ≠ `Int`=64,重声明必须机词;
- **墙 3 局部重声明不可能**:`struct stat` 20 字段,2 字段的 eko 记录
  按值互传会被写穿——重声明要么完整(div_t)要么 shim 分解。

**F16 布局记录包**(已裁):

- 拼写 **`ctype`**——注解槽位第二词(与 `type`/`test` 同位):
  `StatResult: ctype = [ok: I32, size: I64, mode: U32, err: I32]`;
- **显式标记必须**,三塌点:①编译顺序——接口不能依赖更晚编译模块的
  用法(DAG/增量编译);②错误 locality——隐式世界里错误报在用点文件、
  因在声明文件;③知情——表示钉住是成本,成本必须可见;
- 字段限**机词/嵌套 ctype/`C.Ptr.T`**——宽度与 C 头逐一对眼
  (`div_t` 例:`[quot: I32, rem: I32]`);声明序=C 序、C 对齐补白;
- **按值过界是唯一方式**(入参/返回);无引用语义、无 copy-out 机器;
- **出参不入 extern 签名**——shim 吸收为按值返回(F8"绑定携 shim"
  升格为出参唯一通道);
- **完整重声明原则**(用户 S2 原则落地);大/不透明结构 shim 分解;
- **无取址**——eko 值的地址不外借,`&` 永住 C 侧,07 §9 完整存活;
- 环定理/B5 不破:布局记录是不可变堆值,C 只见副本或 shim 自管内存,
  无回写通道;冻结由声明自担(B5 例外收窄到显式 `ctype`)。

**F17 `C.In T` 读借用**(已裁):受审计的调用期读借用——copy-in、
调用期有效、值不变;编译器对自己的临时取址(程序无取址词汇,与
String→`const char*` 既有 marshalling 同形的一般化);选 `C.In` 即
声明"C 只读不保留不写",与 `Pure` 同级审计契约;读类 `&` API
(bind/sendmsg/setsockopt)去 shim;写类 `&` API(出参)仍 shim-only;
Bytes/String 是否统一入 `C.In` 拼写,入定案档。

四例即规范草案形状:div 直绑 / stat shim / bind `C.In` 无 shim /
SqLite 不透明指针回传(F6)。

### 3.15 嵌入 ABI:薄面与任意线程(O7/O8,第五轮)

两个预推演开路:

- **任意线程结构性便宜**:语言无全局可变状态;共享值原子计数已在
  (07 §4.2);闭包与捕获快照不可变。补一条**跨界即共享、共享即
  原子**(与 Conc spawn 捕获同入原子计数类,判定时机属实现域)后,
  两宿主线程并发调同一 eko 函数无数据竞争,各得各的纯值;剩余风险
  =束的线程安全,由束作者(宿主)担保——与 `Pure` 同级审计契约。
  不需要注册线程、全局锁、运行时。
- **O8 第三路**:D2 全细节化与嵌入可移植性对立;全规格化冻死 RC 头/
  闭包布局(07 §5 之死);Lua/WASM 式**不透明薄面**只承诺函数签名,
  `eko_value` 全程不透明——布局零承诺,签名稳定可测;宿主要快可
  直调生成 C(快路=编译器细节,D2 保留给快路)。

全景代码例(双线程编辑器嵌入:veneer/真束假束/γ′ 直调/Conc 束/
跨线程传值)见第五轮对话,定案档收录为规范草案。

**F18 不透明薄面**(O8,已裁):约 15 个函数签名入契约——eval/
get_export/call/retain/release、值构造与读取、能力构造器(递 C
fn+ctx,编译器包成 eko 闭包)、panic 观测(best-effort,R3.4);
`eko_value` 全程不透明;一致性测试可只链薄面。

**F19 持值与线程**(O7,已裁):持值=裸 `eko_retain/eko_release` 于
不透明指针,返回即持有、弃即释放——无 handle 表(变相根注册+
值的第二表示,与 07 §4"宿主持值即持引用,无根注册"相抵);线程=
**任意线程可调**,协议三句:无全局可变状态、跨界即共享共享即原子、
束线程安全由束作者担保。

**F20 细目双条**(已裁):shim 与 extern **共用符号解析面**——链接
期同名即达,一个符号空间无第二套词法,shim 是 C,审计基与 C 库
同级(F8"绑定携 shim"补此句);**Conc 调度属宿主束**——语言只定
语义(06 §8),线程池/调度器宿主供,CLI 默认束=编译器生成。

### 3.16 O1 尾:wrap/unwrap 对与符号保留(第六轮)

B′ 最后一层拼图。派生表要的不只是拆(unwrap: cap→束),更要成
(wrap: 束→cap)——`Out.null` 要造新 Out。配对后 prelude 全景:

```eko
_OutB: type = [write: (String) !]                             // 私有束型(05 §5 `_` 前缀)
Out.unwrap: (Out) -> _OutB  = extern "eko_out_unwrap" Pure     // A3 已废:Pure 任何模块可声明(F5);护栏=F23 符号保留
Out.wrap:   (_OutB) -> Out   = extern "eko_out_wrap"   Pure    // 成束——伪造面所在,同锁
Out.println: (o: Out, s: String) ! = o.unwrap().write(s)       // 操作一行化
Out.null: () -> Out = Out.wrap({write: (s): _})               // 派生=纯组合
Out.tee: (o: Out, obs: (String) !-> _) -> Out =               // 只构造不调用→纯(rule 1)
    b := o.unwrap()
    Out.wrap({write: (s): b.write(s); obs(s)})
```

- 位账:`println` 调 `!` 闭包→位 `!`;`tee`/`null` 只构造→纯
  (rule 1,mk_logger 先例)——R1.2(派生表零宿主魔法)兑现,
  宿主魔法收窄为每能力一对符号。
- **F21 wrap/unwrap 双原语**(已裁):每能力一对,prelude-only Pure
  extern(F5 同词法);束型=prelude 私有记录;unwrap 只读,wrap 是
  伪造面——两者同锁(pure extern 仅 prelude,A3)。
- **F22 prelude 零 libc 直呼**(已裁):OS 面全住宿主束闭包(C 侧),
  prelude 只组合;prelude 的 extern 面恰为 wrap/unwrap 符号对;
  README 开放问题终答:**extern 词法统一到底,intrinsics 不增**
  (05 §11 编译器生成清单维持派生服务/`panic`/内存操作三样)。
- **F23 宿主符号命名空间保留**(已裁):`eko_` 前缀(或等价清单)
  保留;用户 extern 声明保留符号=编译错误——堵"用户自 extern
  `eko_out_wrap` 伪造能力/extern `eko_release` 造 UB"洞;词法层
  的"仅 prelude"拦不住链接层,保留规则是 F14 链接层授权世界观
  的自然延伸。

## 4. 伞形项逐项

### 4.1 机词族(R4.1)

- **转换族**:命名全拼惯例(08 §4)——`to_i8`/`from_i8`…域外→`Option`
  (既有惯例);**已裁(F15)**:→`F32/F64` total(舍入,C 同构),
  →机整词 `Option`,机→域恒全(拓宽)。
- **算术溢出**:**已裁(F15)**——机词零算术(能持/比/显/渡,算回
  域词;legacy/bytes.md §1"能持不能算"同款移植);域词 panic 不变
  (02 §6.2);一条溢出规则零例外。
- **服务面**:`==`/`<`(有,同型)、`show`(全拼数值)、parse 族、
  `U8` 定宽 hex(R4.5)、Dict 键域(有 `==` 即数据型?机词是否
  "数据型"入定案档)。成本表补行。

### 4.2 位算(R4.2)

- **承载者**:位移语义依赖位宽——机词承载最诚实(每类型自带宽);域词
  64 位恒宽亦可承载。倾向(不下定案):机词 only(位算=机界),域词
  算法先 `to_u64`,与"缩写即机界信号"(C1)同构。
- **命名族**:`band/bor/bxor/shl/shr/…`(b-前缀避让 `Bool.and` 混淆)
  或位算专属名。开 O10。
- **运算符解冻**:`& | ^ << >> ~` 预约在案(02 §7);解冻须裁:优先级
  表补行(02 §6)、一元 `~` 词法确认、以及 **`&`/`|` 的 or-pattern 双
  预留让位**(02 §7 明文"留给位算与 or-pattern"——先到者得,后到者
  另谋)。
- 位算纯函数、不置位;溢出语义随 O9。

### 4.3 `0x/0b` 字面量(R4.3)

- 归属位算档(02 §7 既定);解析依期望型(`Int`/`UInt`/机词),与既有
  字面量同机制,无后缀文化;
- 大小写(`0xFF` 允许?)、数值范围检查(域外=编译错误,同十进制)。

### 4.4 `Bytes↔[]U8` 零拷贝(R4.4)

- **安全论证**:`Bytes` 与 `[]U8` 皆不可变;零拷贝=O(1) 共享,不引入
  新边类型(同一堆对象换一个类型透镜),环定理与成本表(07 §7)不受;
  单态化下 `[]U8` 元素直存 8 位槽,与 `Bytes` 内部布局是否真的可共享
  属实现域——**规范只承诺 O(1)**,不承诺物理同址。
- 命名:镜像 `to_ints/from_ints`(08 §3.2)——`to_u8s/from_u8s`(legacy/bytes.md §1 被否决备选已用此拼写)。

### 4.5 FFI 调试定宽 hex(R4.5)

- 命名族挂机词(`U8.to_hex_pad`?)或挂格式化族(09 §2,`to_fixed`
  同款);补零语义候选:"只补不截"(`pad_left` 同款原则)。
