# Design Record — 2026-10 Audit Rulings

Non-normative. Ruled items of the 2026-10 audit, with the rejected
alternatives. Clauses touched: 5–7, 9, 10, Annexes A and B. The ten confirmed
items record no decision — the normative clause states their reading.

## 1. `:=` never opens a block

**Ruling (2026-10-26).** The block-opening tokens are `:` and `=`; a line
ending in `:=` opens no block, and a multi-line rebinding right-hand side is a
continued expression, spliced, never a `NEWLINE INDENT … DEDENT` wrapper
(`Clauses 6.2.3, 6.2.4`; Annex A.4 rule 6). A block license for `:=` would add
a third opener and split the header table into declarations versus rebinding
statements. Python and Go also assign without opening a block.

## 2. A qualified name's head is the module (Annex A.3.8)

**Ruling (2026-10-26).** `QualifiedPascalName` is `{ Identifier '.' }
PascalName`: an any-case module head, one PascalCase last segment, exactly one
module segment (`Clause 7.4.4`); a longer dotted prefix is `E-unbound-name`.
Module stems are snake_case (`Clauses 5.5.2, 7.2.1`), so OCaml's capitalized
`Mod.Type` does not transfer — the mechanism kept is head-names-the-module, not
casing. A module-qualified constructor application is a call,
`geolib.Circle(r)` (`Clause 6.5.2`); `Mod.Type.f(args)` calls on the qualified
type and `x.Mod.Type.f(args)` supplies the receiver.

## 3. One arm's patterns bind together

**Ruling (2026-10-26).** A multi-scrutinee `case` arm carries one pattern per
scrutinee (`Clause 6.7.2`) and constructs no tuple value, so the per-pattern
duplicate rule did not formally reach it. The arm's patterns bind together as
one pattern: a name occurring in two of them is `E-name-conflict`
(`Clauses 6.8.6, 7.4.6`). Rust and Swift reject a repeated binder in one
pattern; neither has a multi-scrutinee arm, so this generalizes their rule.

## 4. A floating literal must be finite

**Ruling (2026-10-26).** A floating literal denotes a finite `Float`; a value
that is not finite after conversion is `E-literal-overflow`
(`Clause 5.7.2`, Annex B.3). The condition is the one `Clause 5.7.1` names with
`Float` as target, so no separate code. Operations may overflow to `inf`;
literals may not — a literal is a placement, checked at compile time.

## 5. Constructors are anchored, not layered

**Ruling (2026-10-26).** Constructors never conflict by visibility: same-named
constructors of different types coexist, anchored by the expected type in value
position (`Clause 7.5.2`) or the scrutinee type in pattern position
(`Clause 7.7.1`). An unanchored reference is legal only when exactly one
visible constructor of that name is non-generic (`Clause 7.6`); otherwise an
annotation anchors it. Opened type names keep a shadowable fallback layer
(`Clause 7.2.5`); free names follow the ordinary import rules
(`Clauses 7.4.6, 9.1.2`). The occlusion model would have let a user
`MyBool: type = True | False` reject a correct `x: Bool = True`, and a default
`Bool` rule would silently choose std's constructor. Rust's variants are
anchored the same way.

## 6. `with` is record construction from a base

**Ruling (2026-10-26).** `r.with({...})` builds a new record of the receiver's
type: named fields from the literal, the rest from the receiver, the original
unchanged (`Clauses 6.6.3, 9.8.6`). The partial literal descends through record
field values only — a list, dictionary, or tuple element is a complete value,
and a partial literal there is an error. `with` is a construction primitive
wearing member-call syntax, not a function: its second parameter type is
unspellable and the literal is legal nowhere else. Rust's `..p` base completion
is the same rule one layer deep.

## 7. Selective import

**Ruling (2026-10-26).** std is an ordinary file module: the compiler's only
act is the injected `import std.{assert, assert_eq, assert_ne}` line, no name
rewriting occurs, imports open types, and functions stay module-qualified
(`Clause 7.2.3`). The three names are ordinary std source.
`show`, `inspect`, and `panic` are compiler-generated services attached to type
namespaces; each free-call form is the identity of `Clause 6.5.2`. An opened
free name collides at the declaration point — with a file top-level binding, or
between two imports — as `E-name-conflict`; locals shadow legally
(`Clauses 7.2.3, 7.4.6`). A new std free function is immediately usable
qualified, and bare for any file that imports it; the injected list moves only
by language revision, as Rust's prelude does (`Clauses 6.1, 7.2.5, 9.1.2,
9.2.3, 9.8.1, 9.14.3`). New std types open automatically and are shadowable, so
they are non-breaking; new namespace members ride their types and are reported
as breaking by default, because a new member can silently win station 2 over a
user's station-3 function (`Clause 7.4.3`) — a recorded, deliberately unfixed
hazard.

## 8. Corpus rulings (2026-10-27)

The example corpus (a todo application and a Lua interpreter, ~2,300 lines) was
run through the finished front half and its residual diagnostics ruled one by
one.

- **G1, arm bodies open blocks.** A `case` arm line ending in `->` opens the
  arm body; the last member is the value (`Clause 6.2.3`, Annex A.4 rule 6).
  The opener is token-based: a depth-zero line ending in `->` opens a block
  even where an annotation might have been meant, and the grammar now rejects
  that at parse instead of layout silently splicing it.
- **G2, type aliases stay out.** `Name: type = <type expression>` remains
  illegal (`Clause 6.9.5`, the 6.10 table). Go ships without aliases by choice;
  the Haskell `type`/`newtype` split is the confusion avoided.
- **G3, composite generic arguments stay parenthesized** (confirmed audit
  item 7): `Result ([]String) String`, never the bare form, which is lexically
  indistinguishable from a juxtaposed application. The corpus is corrected.
- **G4, calls keep their parentheses.** Juxtaposition is constructor
  application only (`Clause 6.5.2`); `Int.to_float i` is an error.
- **G5, the empty interpolation slot stays an error.** `"{}"` is
  `E-empty-slot`; a literal brace is `"\{"` (`Clause 5.9.3`). Corpus corrected.
- **G6, an example defect.** The interpreter's `_index_get` disagreed with its
  caller; corrected to `Result ([State, Value]) String`. No spec change.
- **G7, `==` stays value-layer.** ADTs compare through the derived `eq`
  (`Clauses 7.8.3, 9.8.4`); the example lines become `.eq` calls.
- **G8, operand lambdas are parenthesized** (corrigendum, 2026-10-27).
  `if (a) || (b): 1 else: 2` misparsed, `(b)` reading as a lambda's parameter
  group and swallowing the header's colon. In operand position — a unary or
  binary operand, or the juxtaposed constructor argument — `( parameters ) :`
  is a grouping followed by the header colon, and a lambda there must be
  parenthesized (`Clause 6.4.1`). Swift requires the same in ambiguous
  positions; house style already demands it for composite generic arguments.

## 9. Front-end rulings (2026-10-28)

The front half was audited clause by clause against the implementation.
Implemented and tested unless marked pinned (normative text only).

- **Binding lines admit every pattern.** The left of `=`, `:=`, `<-` parses the
  full pattern grammar; refutable families ride to check, which owns
  `E-refutable-binding`. A qualified pattern spelling ends in its constructor,
  and an annotation may follow any pattern.
- **`else` matches its `if` by column.** Past a line boundary, reattachment
  holds only at the header's column; an `else` matching no open header is an
  error where it stands.
- **A `case` or `if` argument is parenthesized**; no block is expected there
  (`6.5.1`).
- **The case class reads the Unicode table.** PascalCase is Lu/Lt of the first
  scalar; the ASCII approximation misread every non-Latin type name. The XID
  tool emits the category ranges.
- **An unknown constructor name is unbound.** Only the compiler-provided
  placeholder rows survive resolution; a misspelling is `E-unbound-name` at
  value and pattern heads alike.
- **Public surface spells public types.** `7.3.3` covers public bindings,
  externs, namespace members, and the payload and field surfaces of public
  types and ctypes.
- **One module per stem, at the root too.** The root's file is spelled by the
  host, so a same-stem import cannot be compared to it as a file: the stem is
  the identity, the import denotes the root, and the back edge is the cycle
  reported (`7.2.4`).
- **The frozen clock's mono reading is `Mono 0`** (pinned): any constant would
  conform; determinism tests need one number.
- **The assert family fails through `P-panic`** (pinned). The dedicated codes
  promised an output no ordinary std source can produce; they leave Annex B.5.
- **Comments do not occur inside interpolation slots** (implemented). A slot's
  content is an expression; `//` and `/*` there lex as operators.
- **The `extern` word needs its string.** `extern` before a string literal
  begins the declaration; elsewhere it is an ordinary name (`5.6.2`).
- **Coverage is judged at depth.** A guarded arm contributes nothing; a
  constructor split in a multi-scrutinee case owes its payload, judged over the
  rows surviving every further split; a scalar column splits the literals its
  rows name from the catch-all; a scrutinee without case structure is covered
  only by a variable or `_`.
- **Capability names carry no `std.` spelling.** The placeholder rows open the
  nine names unqualified; the qualified reading is `E-unbound-name`, because
  std carries no capability content (`9.1.1`).

## 10. Known deviations

The five front-end items recorded here earlier — chain-station shadowing, the
instantiation guard, undetermined variables, product shape columns, the silent
width caps — are implemented and pinned by front-end tests.

The std source now declares the value-layer and container members of C.3–C.8,
C.10, C.11 over the compiler's intrinsic rows. Remaining gaps:

- the intrinsic rows std builds on — scalar arithmetic, conversion, formatting,
  parsers; String's scalar access and the Bytes operations; Dict, Set, Range,
  Path; the time parsers; `Json.parse`; `List.append`; the panic-coded
  unwrap/expect pair — need the lower/runtime implementations;
- the `C` native namespace rows (Annex C.2) are unwritten: they need the same
  stage;
- companion modules are fileless stubs — an `std/<stem>` import registers an
  empty module instead of loading a release file (`Clauses 9.1.3, 11.1`);
- std/cap are re-checked per unit rather than per build (`Clause 11.2`).

## 11. Rejected surface

| Item | Rejected | Reason |
|---|---|---|
| 1 | block license for `:=` | a third opener; splits the header table |
| 2 | PascalCase module stems | a second naming convention beside the file stem; qualified calls would spell the other case |
| 3 | OCaml last-wins | a silent shadow inside one arm is a typo shaped like a program |
| 3 | Erlang equality constraint | an accidental repeat becomes an invisible guard; comparison belongs to guards (`6.7.3`) |
| 4 | `E-float-overflow` | slices one defect class by literal kind; `E-literal-overflow` is frozen |
| 4 | `inf` as a literal value | pushes a static defect to run time; two truths for one value |
| 5 | two-layer constructors | occlusion rejects a correct annotation; a name layer forces a winner |
| 5 | default-`Bool` fallback | converts a missing annotation into a silent choice |
| 6 | single-layer `with` | nesting is the natural case: a field is built from the receiver's field |
| 6 | `with` as a function or method | its type is unspellable and its literal legal nowhere else |
| 7 | open-all `import std` | every new std function enters every file silently |
| 7 | module-side designation | the importer's namespace decision taken by the imported file |
| 7 | test-scoped assert names | ordinary source would mean different things by mode |
| 7 | capability-qualified asserts | ties a pure function to a capability it does not use |
| 7 | `Bool.assert` split | `assert_eq` is generic over two arguments, not one receiver |
| 7 | `panic` as std source | `Clause 9.1.1` promises the library sits above the abort primitive |
| 7 | `panic` by a name rule | the six-name list again, for one service |
| G1 | inline suites only | block mechanism already exists for `:` and `=`; corpus uses it pervasively |
| G2 | transparent aliases | erodes nominal identity; the cheap expansion is available by hand |
| G4 | generalized juxtaposition | a grammar change bought at permanent ambiguity cost |
| G7 | desugaring `==` to derived equality | blurs the `E-no-eq` boundary and changes the diagnostic surface |
| G8 | reading the lambda maximally | every parenthesized operand before a header colon becomes unspellable |
| 9 | pre-rejecting refutable shapes at parse | `7.7.1` gives the rejection a static code |
| 9 | the innermost-if `else` grab | attaches an outer `else` to an inner `if`, changing the tree |
| 9 | eager payload coverage at its column | a later column's split can remove the row that covered it |
